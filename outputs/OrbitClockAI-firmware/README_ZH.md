# Orbit Clock AI：像素时钟、小游戏和小智语音合并版

[English](README.md)

这是基于小智 v2.5.2 的自定义合并工程，适用于 Waveshare ESP32-S3-Touch-AMOLED-2.16（16MB Flash、8MB PSRAM）。它继续使用当前像素时钟和小游戏的界面、资源及规则，并加入“你好，小智”唤醒和在线语音对话。原 Arduino 时钟工程和已编译固件单独保留。

## 直接烧录与首次使用

1. 打开任务目录 `outputs/OrbitClockAI.code-workspace`，使用 VS Code 的“终端 → 运行任务”。
2. 选择 **小智合并版：直接烧录并校时（ROM 模式，不备份）**。已提供编译好的文件，这一步不需要先编译。它使用 115200 波特率和 ROM 下载器，避免之前上传 stub / 高速备份时的串口中断。任务名称中的“不备份”表示这次不创建板上 16MB 完整镜像。
3. 首次没有 Wi-Fi 配置时，按屏幕提示连接 `Xiaozhi-xxxxxx` 热点，在浏览器打开 `http://192.168.4.1`，配置 **2.4GHz Wi-Fi**。
4. 如果提示六位激活码，在 [小智控制台](https://xiaozhi.me/) 登录并添加设备，输入板子提示的激活码。已有绑定是否仍有效，以设备和控制台的实际提示为准。
5. 激活成功后，回到时钟页面说 **“你好，小智”**。也可以长按时钟上的时间，在设置中点击 **小智 AI**。
6. 单击 **Key3**，结束对话并返回原来的时钟 / 游戏页面。语音页、配网和激活界面均已移除“返回时钟”屏幕按钮；仍可通过 Key3 离开，再从菜单回到小智界面。

配网、六位激活码和唤醒词来自 [Waveshare 小智官方教程](https://docs.waveshare.net/ESP32-S3-Touch-AMOLED-2.16/XiaoZhi_AI/)。本工程中的合并界面、游戏暂停和返回操作属于本次自定义开发。

## 自动联网、Key2 与校时

- 开机自动读取已保存的 Wi-Fi，优先连接最近成功联网的网络；它不在附近或无法连接时，再尝试其他已保存网络。连接成功会保存优先顺序，断电后保留，不删除其他网络密码。
- **单击 Key2（BOOT / GPIO0）**：按下即显示“Key2：检查网络”，松开时触发操作，连续点击也不会被双击判断吞掉。离线时手动重试已保存网络；正在连接时不重复启动；已经联网时重新校时，保留当前语音连接。Key2 不再作为打开语音界面的快捷键，语音唤醒和设置菜单入口保留。
- 没有保存的网络，或启动连接超过约 60 秒仍未成功时，会进入配网。按提示配置 2.4GHz Wi-Fi；在配网页面单击 Key2，有已保存网络时会退出配网并重试连接。没有保存网络时，Key2 会重新显示配网提示，即使此前返回了时钟页面。
- 每次获得网络连接后自动向 NTP 服务器请求时间，显示北京时间。屏幕会区分“正在连接”“正在校时”和“网络校时成功”；30 秒未收到校时回应会提示未成功，联网状态下稍后自动重试，也可以再按 Key2。原有 USB 电脑校时仍可使用。
- 时钟和小智使用同一个 Wi-Fi 管理器。联网事件继续进入小智原有的激活和对话流程；在线对话仍需要可访问互联网的网络和已完成的小智设备激活。连接路由器与校时成功不会被当作云端对话已经通过验证。

Key2 对应关系参见 [官方板卡说明](https://docs.waveshare.net/ESP32-S3-Touch-AMOLED-2.16/#gpio-引脚分配)。这里只改变设备正常运行后的单击行为，开机下载模式仍使用原有 BOOT 操作。Key3 的全部游戏切换和返回规则保留。

合并版的 CO5300 方向寄存器已与之前正常的时钟固件对齐，取消额外硬件镜像；触摸先转换到相同屏幕坐标，再随页面旋转。所有页面共用这套方向设置。

**正方向以屏幕朝向自己、三颗物理按键位于上边缘为准。** 根据实板反馈中“此时画面向右倒 90°”的情况，本版在最终刷屏层固定向左修正 90°，原始触摸坐标做对应的逆变换。时钟、游戏、小智和配网页面一起生效，旧的方向锁定值也会经过这层修正；保留已保存的游戏、Wi-Fi 和方向设置。手动校准的第一步也以三颗按键朝上作为摆放基准。

本版为触摸数据读取补齐 `D0 00 AB` 确认，并每 20ms 读取触摸状态，避免旧触点或按下状态一直残留。固定使用经过验证的 CST9217 组件 1.0.4，下载的组件源码保持原样，由本板适配层完成确认和出错时释放旧触点。游戏设置按钮按下时变暗，并扩大少量点击范围；骰子数量 / 面数、沙漏开始 / 设置、玩家设置都使用同一条修正后的输入路径。软件检查覆盖这些按钮在四个方向下的实际点击和松手。

流沙主界面取消独立“开始”按钮。**点击沙漏、时间数字或背景开始，再次点击暂停，再点继续**；结束后点击可重新开始。底部只保留加宽的“重置”按钮，点击会恢复设定时长，不会同时开始计时。**长按屏幕 2 秒**进入时长设置，允许手指轻微抖动，明显拖动会取消本次操作。长按打开设置后，松手不会同时启动计时或误点设置按钮。Key3 返回操作保持原样。

合并版已移除旧“开始 / 暂停”和旧“重置”的按钮回调与左右按钮布局。页面点击由独立事件处理；底部新重置按钮只在可见范围内有效，按钮外没有额外扩大的重置热区。点击沙漏右侧背景只会切换开始 / 暂停，不会重置剩余时间。

一次完整按下、松手只执行一次操作。**切换开始 / 暂停后，至少等 0.5 秒，再次按下屏幕才会接受下一次切换**；间隔不足的点击会忽略。长按 2 秒优先进入设置，按住期间不会开始 / 暂停，松手后也不会追加一次点击。驱动会过滤短暂无效包和假松手，真实松手确认约需 80ms；连续没有有效触点报告时最多保留 1.2 秒，随后释放，避免一直卡在按下状态。

**首次进入流沙时，没有触摸校准记录会自动显示三个圆点的校准流程。** 屏幕朝向自己、三颗按键在上方，按提示依次点击当前圆点并松手。显示“校准完成”后自动返回；坐标校准会保存，断电后仍有效。校准直接读取原始触点，不依赖当前可能错误的按钮热区，可以修正右侧触摸却命中底部重置的坐标错位。以后**按住 Key3 三秒**可重新校准；校准中单击 Key3 取消，保留原记录。Key3 原来的单击返回和双击进入下一游戏不变。

## 保留的操作

| 页面 | 触摸操作 | Key3 操作 |
| --- | --- | --- |
| 像素时钟 | 点击切换皮卡丘形态并播放音效；点击时间切换时制；长按时间打开设置 | 单击进入骰子 |
| 专注计时 | 自定义 1～180 分钟，开始、暂停、重置 | 保留原来的游戏入口 |
| 骰子 | 晃动后转动 2 秒出结果；长按设置 1～3 颗、2～8 面；2 面固定一颗正反硬币 | 单击返回时钟；双击进入流沙 |
| 流沙倒计时 | 点击页面开始 / 暂停 / 继续；底部加宽重置；长按 2 秒设置 1～3600 秒 | 单击返回骰子；双击进入玩家转盘 |
| 开始玩家 | 点击转盘或“开始”；先转 3 秒再减速；长按设置 2～12 人 | 单击返回流沙 |
| 小智语音 | 在线语音对话；黑底动态眼睛表情 | 单击结束对话并返回原页面 |

自动转向默认仍保持原有锁定策略，可在设置中校准或锁定方向。皮卡丘音效沿用用户选定的前 2.2 秒片段，合并版转换为 Opus 后通过小智统一音频服务播放，连续点击不会排队重播。播放这段音效期间暂时关闭唤醒检测，结束后恢复，避免音效触发语音识别。

语音界面打开时，骰子掷骰和玩家转盘会取消当前动画；流沙保留剩余时间并暂停，返回后点击继续。专注倒计时继续走时。游戏页和设置不会因为进入语音而被删除。

## 自定义小智表情

使用用户提供视频中提取的眼睛 GIF：先显示带粉色腮红的眼睛，再播放变化的眼睛形状，5.8 秒循环。拍摄中的镜头平移已校正，设备外壳、顶部状态文字和旁边介绍文字已去除；实板资源为 400×180 像素、20fps，保留拍屏素材原有的轻微模糊。

资源索引参照 [xiaozhi-assets-generator](https://github.com/78/xiaozhi-assets-generator) 的 `emoji_collection` 和 `skin` 格式，所有 21 种标准情绪指向同一个 GIF 文件，不包含 21 种不同动作。浅色 / 深色主题都设置为黑底白字。编译时先由锁定版本的小智官方脚本生成原资源，再由 `scripts/generate_orbit_ai_assets.py` 合入表情，使用同一官方打包器生成 `assets.bin`，保留唤醒词模型、中文字体和字体元数据。普通编译或再次准备工程不会丢失自定义表情。

语音页面显示时播放动画，返回时钟或游戏后暂停解码，避免表情持续占用后台刷新。小智界面不再显示“返回时钟”按钮，Key3 返回和关闭对话的操作保留。GIF 表情不影响时钟的皮卡丘图像或点击音效。

## 固件与现有设置

烧录任务会先校验 5 个文件的 SHA-256、长度、地址和实际分区表。使用独立文件写入，不执行整片擦除，保留 `0x9000` 开始、大小 `0x5000` 的 NVS，以及原游戏和方向校准使用的命名空间 / 数据类型。

| 文件 | 写入地址 |
| --- | --- |
| `bootloader.bin` | `0x0` |
| `partition-table.bin` | `0x8000` |
| `ota_data_initial.bin` | `0xe000` |
| `orbit-clock-ai.bin` | `0x20000` |
| `assets.bin` | `0x800000` |

本合并版的应用地址是 **0x20000**，与原 Arduino 版的 0x10000 不同。请使用合并版任务和对应清单。保留分区不等于创建了完整备份；若需要完整板上镜像，可以在命令行省略 `--skip-backup`，备份失败时任务会停止。

本工程使用独立板型 `orbit-clock-ai`，并关闭网络固件升级，防止云端固件替换这套时钟和游戏。服务器配置 / 激活请求仍保留。之后更新合并版请通过 USB 烧录。需要恢复原版时，在同一工作区选择 **原时钟游戏版：恢复烧录（ROM 模式，不备份）**。

## 开发与编译

维护入口是本目录的 `board/`、仓库 `scripts/orbit_ai.py` 和 `scripts/generate_orbit_ai_port.py`。像素时钟和游戏的公共实现继续放在 `examples/arduino/08_OrbitClock`。

在仓库根目录执行：

```sh
python3 scripts/orbit_ai.py prepare
python3 scripts/orbit_ai.py build
python3 scripts/orbit_ai.py flash --skip-backup
```

`prepare` 将官方 [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32) v2.5.2（提交 `49b4380b3faa0ceadd28a3e78aaf0f311c46c57e`）准备到任务目录 `work/xiaozhi-upstream`，新增自定义板型并生成 LVGL 9 适配文件。不要直接修改 `work` 下的生成文件；下一次准备会重新生成。

使用官方支持的 ESP-IDF **6.0.1 或更新版本**，推荐 6.1。脚本读取 `IDF_PATH`、`IDF_TOOLS_PATH`、`IDF_PYTHON_ENV_PATH`；本机未显式指定时使用已安装的 6.1 环境。本次交付实际使用官方 ESP-IDF 6.0.1、对应推荐的 Xtensa GCC 15.2 工具链完成编译；未修改电脑已有的 ESP-IDF / Python 安装。构建目录和依赖缓存均在任务目录 `work` 内。

显示迁移只适配接口、字体、图像格式和 DMA 刷屏。四向显示与触摸沿用已有校准映射；矩形采用直接填充，避免三角拆分在像素数字内留下接缝。LVGL 使用两块有界 PSRAM 池，声音仅由小智的 AudioService / ES8311 / ES7210 驱动管理。额外的策略选项关闭网络固件升级，并让服务器时间保持 UTC，交由 `CST-8` 时区显示北京时间，避免偏移两次。

## 验证范围

- 完整 ESP32-S3 合并固件已编译并检查分区容量。
- 主机界面检查覆盖时钟、双形态、专注、19 种骰子配置、沙漏、玩家转盘、四向显示 / 触摸、局部刷新一致性、设置、Key3 路由和语音界面切入 / 返回。
- 音频检查运行实际音效提交代码与官方 Ogg 解析器，验证连续点击不重播、离线配置时可播放、播放结束恢复唤醒、队列超时和 AI 对话优先。
- 烧录文件检查拒绝错误地址、缺文件、内容损坏、越界、错误分区表和覆盖 NVS 的镜像。
- 表情资源检查保留唤醒模型、字体与元数据，验证全部情绪共用一个文件、重复生成一致、损坏索引被拒绝；实际小智 GIF 解码器连续两轮 232 帧与 Pillow 逐像素一致，实际播放控制器的暂停 / 恢复 / 停止及反复释放检查通过。

可在仓库根目录重新检查：

```sh
python3 -m unittest discover -s tests -v
python3 scripts/orbit_ai.py test
python3 scripts/check_orbit_ai_ui.py
python3 scripts/check_orbit_ai_emotion.py
```

表情主机检查额外需要 Pillow，使用前先完成界面检查以准备原生 LVGL。

交付时**尚未在实板烧录或验证麦克风、真实唤醒率、扬声器与联网对话**。首次上板请先检查时钟 / 触摸 / Key3，再配网激活，最后测试“你好，小智”、语音返回和皮卡丘音效。

整屏触摸没有反馈时，不能仅凭主机模拟判断已恢复。串口 `STATUS` 除原有状态外会输出 `ORBIT TOUCH`：本版标识 `sand_stable_v4`、触摸读取次数、有效触点报告数、错误数、错误码和原始坐标，用于区分固件版本、没有触点与坐标命中问题；这些计数不代替实板触摸验证。
